# PokéType Dojo 2時間開発イベント計画

## 目的

**PokéType Dojo** は、子どもの頃にポケモンを遊んでいた大人向けに、ポケモンのタイプ相性を学び直せるミニアプリ。

サブコピー:

```txt
タイプ相性を、かわいく鍛え直そう。
```

特に、フェアリータイプ追加後の相性が曖昧になっている人でも、タイプ相性チェッカーやクイズを通じて楽しく覚え直せるようにする。

## イベント前提

- 複数人がそれぞれ2時間でアプリを開発するイベント。
- 2時間後に自分の作ったアプリを発表する。
- 商用利用はしない。
- AIを使って開発する。
- TanStack Startの良さも活かす。
- データ準備は事前に行ってよい。
- イベント中に外部API、データ調査、seed整形へ依存しない。

2. タイプ相性チェッカー

4. リージョンフォーム、メガシンカ、キョダイマックス、フォルム違いの出題

## データ方針

PokeAPIを当日叩かず、事前に必要なデータを用意してアプリ内で扱う。

タイプ一覧とタイプ相性は小さく固定的なデータなので、TypeScriptの静的データとしてコミットする。ポケモンのタイプ当てクイズ用データは、実装する場合のみイベント前に構築し、SQLite + Drizzleに格納する。

この判断は [ADR 0001](./adr/0001-static-type-effectiveness-data.md) に記録する。

### 静的タイプデータ

ファイル:

- `src/data/pokemon-types.ts`: 18タイプのID、日本語名、表示色
- `src/data/type-effectiveness.ts`: 18×18の倍率データ
- `src/data/effectiveness-labels.ts`: 倍率の画面表示と効果文

タイプ相性データはPokeAPIを生成元にする。PokeAPIの `double_damage_to` / `half_damage_to` / `no_damage_to` を事前に取得し、18×18の `type_effectiveness` 配列へ正規化する。

生成後のspot check:

- `でんき → みず = 2倍`
- `でんき → じめん = 0倍`
- `こおり → ドラゴン = 2倍`
- `フェアリー → ドラゴン = 2倍`
- `ほのお → みず = 1/2倍`

### ポケモンクイズ用データ

イベント版でポケモンタイプ当てクイズを実装する場合、対象は第1世代151匹の通常個体に固定する。タイプは初代当時ではなく、現在の公式タイプを使う。

将来的には `generation` 追加で第2世代以降を増やせるようにし、リージョンフォームやメガシンカなどは元ポケモンに紐づく `pokemon_forms` として表現できるようにする。

イベント版の最小形:

```ts
type PokemonQuizRecord = {
  id: number;
  name: string;
  jaName: string;
  type1: PokemonType;
  type2: PokemonType | null;
  spriteUrl: string;
  generation: number;
};
```

`type1` / `type2` は表示順として保持する。ポケモンタイプ当てクイズの正誤判定では順序を問わず、タイプの組み合わせが一致すれば正解とする。

## 型と計算

### PokemonType

```ts
export const pokemonTypes = [
  "normal",
  "fire",
  "water",
  "electric",
  "grass",
  "ice",
  "fighting",
  "poison",
  "ground",
  "flying",
  "psychic",
  "bug",
  "rock",
  "ghost",
  "dragon",
  "dark",
  "steel",
  "fairy",
] as const;

export type PokemonType = (typeof pokemonTypes)[number];
```

### Effectiveness

```ts
export type Effectiveness = {
  attackType: PokemonType;
  defenseType: PokemonType;
  multiplier: 0 | 0.5 | 1 | 2;
};
```

### 計算仕様

タイプ相性は「技のタイプ → 攻撃されるポケモンのタイプ」で決まる。

単タイプ:

```ts
finalMultiplier = getMultiplier(moveType, defendingType1);
```

2タイプ:

```ts
finalMultiplier = getMultiplier(moveType, defendingType1) * getMultiplier(moveType, defendingType2);
```

防御側タイプの順序に、計算上の意味はない。

相性計算ロジックは `src/utils/effectiveness.ts` に置く。チェッカー、タイプ相性クイズ、将来のタイプ相性表で共通利用する純粋関数として扱う。

最低限の関数:

- `getSingleMultiplier`
- `getFinalMultiplier`
- `formatMultiplier`
- `getEffectivenessMessage`

表示:

| 内部値 | 倍率表示 | 効果文             |
| -----: | -------- | ------------------ |
|      0 | 0倍      | 効果がない         |
|   0.25 | 1/4倍    | 効果が今ひとつ × 2 |
|    0.5 | 1/2倍    | 効果が今ひとつ     |
|      1 | 1倍      | 等倍               |
|      2 | 2倍      | 効果は抜群         |
|      4 | 4倍      | 効果は抜群 × 2     |

### テスト

相性計算ロジックにはユニットテストを書く。

最低限のテストケース:

- `でんき → みず / ひこう = 4倍`
- `でんき → みず / じめん = 0倍`
- `こおり → ドラゴン / ひこう = 4倍`
- `ほのお → みず = 1/2倍`
- 防御タイプが1つだけでも正しく動く

## タイプ相性チェッカー

### 目的

ユーザーが技タイプと攻撃されるポケモンのタイプを選ぶと、相性倍率を即時表示する。

### 表記

画面では「攻撃タイプ」「防御タイプ」ではなく、以下の表現を使う。

```txt
技のタイプ
攻撃されるポケモンのタイプ
```

理由:

- ポケモンのタイプ相性は「技のタイプ → 攻撃されるポケモンのタイプ」で決まる。
- 「攻撃するポケモンのタイプ」と誤解されるのを避ける。

### タイプ選択UI

Selectではなく、18タイプすべてをタイプバッジ式ボタンとして表示する。

技タイプ:

- 0〜1つ選択できる。
- 選択済みの技タイプを再クリックすると選択解除する。

攻撃されるポケモンのタイプ:

- 「タイプ1」「タイプ2」の2スロット式にする。
- 編集対象のスロットを選び、タイプバッジをクリックするとそのスロットに入る。
- 選択中スロットに入っているタイプを再クリックすると、そのスロットを空にする。
- もう片方のスロットに入っているタイプは選べない。
- 片方のタイプを固定し、もう片方だけを切り替えて比較できるようにする。
- 「すべて外す」ボタンで防御側タイプを全解除する。

編集対象スロットの自動切り替え:

- 初期状態はタイプ1を編集中にする。
- タイプ1が空で、タイプ1にタイプを入れたら、自動でタイプ2編集中へ移る。
- タイプ2にタイプを入れた後は、自動切り替えせずタイプ2編集中のままにする。
- タイプ1を空にしたら、自動でタイプ1編集中へ戻る。
- 「すべて外す」後はタイプ1編集中へ戻る。

### 未選択状態

初期値は設定しない。`/type-checker` は未選択状態で表示する。

結果表示には、技タイプ1つと攻撃されるポケモンのタイプ1つ以上が必要。どちらかが不足している場合は、結果の代わりに次の一手だけを短く表示する。

- 何も選んでいない: `技のタイプを選んでください`
- 技タイプだけ選んだ: `攻撃されるポケモンのタイプを選んでください`
- 防御側タイプだけ選んだ: `技のタイプを選んでください`

### search params

URL例:

```txt
/type-checker?move=electric&def1=water&def2=flying
```

仕様:

- `move`, `def1`, `def2` を使う。
- 未選択の値はsearch paramsから削除する。
- `def2` が未指定、空、不正値の場合は未選択として扱う。
- `def1` と `def2` が重複している場合は `def2` を未選択として扱う。
- `move` または `def1` が不正値の場合は未選択として扱う。
- 不正値や重複を補正した場合は、`@mantine/notifications` のnotificationでユーザーに知らせる。
- `def1` / `def2` はユーザーが選択したスロットを表す。計算上の意味は持たない。

### 結果表示

倍率を主役にし、ポケモンバトルで出てくるような効果文を添える。

例:

```txt
4倍
効果は抜群 × 2

内訳:
でんき → みず: 2倍
でんき → ひこう: 2倍
2倍 × 2倍 = 4倍
```

画像や演出が用意できる場合は追加してよいが、イベント版では文字だけで分かりやすいことを優先する。

## タイプ相性クイズ

目的はタイプ相性の計算練習であり、実在ポケモンのタイプ組み合わせに限定しない。防御側タイプは1〜2タイプをランダムに選び、同じタイプ2つの組み合わせだけ避ける。

### 出題範囲

画面上では「出題範囲」として表示する。

- 全タイプ (`mode=mixed`): 単タイプと2タイプを混ぜる。イベント版では2タイプ80%、単タイプ20%。
- 単タイプのみ (`mode=single`): 防御側タイプを1つだけ出す。
- 2タイプのみ (`mode=dual`): 防御側タイプを2つ出す。

`/quiz/type-matchup?mode=mixed` のように、出題範囲だけをsearch paramsで扱う。問題そのものの共有はイベント版では行わない。

### 機能

- ランダムな技タイプを出す。
- ランダムな防御タイプ1〜2個を出す。
- 倍率を回答する。
- 正解 / 不正解を表示する。
- 解説として内訳を表示する。
- 次の問題に進める。
- セッション内の正解数 / 回答数を表示する。

回答選択肢は倍率と効果文をセットで表示する。

- `0倍（効果がない）`
- `1/4倍（効果が今ひとつ × 2）`
- `1/2倍（効果が今ひとつ）`
- `1倍（等倍）`
- `2倍（効果は抜群）`
- `4倍（効果は抜群 × 2）`

スマホでも押しやすいように、選択肢は2列グリッドを基本にする。

イベント版では1問ずつ解く形式にする。10問モード、終了画面、localStorageへの成績保存はCouldとして後回しにする。

回答後の表示方針:

- 回答前は全選択肢を通常表示する。
- 正解を選んだ後は正解ボタンをミント〜パステルグリーンで強調する。
- 不正解を選んだ後は正解ボタンをミント系、選んだ不正解ボタンをコーラル〜ローズピンクで強調する。
- 回答後は選択肢をdisabledにする。
- 下に内訳と「次の問題」ボタンを表示する。

## ポケモンタイプ当てクイズ

Could機能。実装できた場合のみ有効化する。

機能:

- DBからランダムにポケモンを取得する。
- ポケモン名と画像を表示する。
- 正しいタイプ組み合わせを4択で選ぶ。
- 正誤判定ではタイプの順序を問わない。
- 正解 / 不正解を表示する。

未実装の場合でもトップページにはカードを表示する。ただし `準備中` バッジを付け、クリックできない状態にする。


## ビジュアルデザイン

CUTIE STREET「キュートなきゅーたい」のジャケットを意識し、淡いキャンディカラー、白いフリル感、クリスタルの透明感がある明るいUIにする。ダークモードは用意せず、1つのライトテーマに絞る。

優先順位:

1. 文字だけでタイプ相性が分かりやすいこと。
2. タイプバッジや結果表示が楽しく見えること。
3. 余裕があれば、きらめきやクリスタル風の装飾を足すこと。

色の方向性:

- 背景: 白、薄いピンク、薄いラベンダー、薄い水色。
- パネル: 白〜半透明の白。境界線は淡いピンクやラベンダー。
- アクセント: ピカチュウの黄色、フェアリー系のピンク、みず系の水色。
- 正解: ミント〜パステルグリーン。
- 不正解: コーラル〜ローズピンク。
- 注意通知: ラベンダーまたは琥珀寄りの淡い黄色。

タイプごとの色は公式タイプ色をベースにしつつ、彩度を少し落としてパステル寄りに調整する。タイプ識別のしやすさを優先し、世界観に寄せすぎてタイプの印象が変わらないようにする。

Mantineはライトテーマ固定で使う。ダークモード切り替えUIは不要。

### Mantine Theme

Mantineのカスタムテーマを作成し、アプリ全体のデザインを統一する。

テーマで定義するもの:

- ライトテーマ固定
- パステル寄りのprimaryColor
- 背景、パネル、境界線、正解、不正解、注意通知の色
- ボタン、カード、バッジの角丸と影
- 見出しのfontWeight

イベント版ではテーマ定義を `src/theme.ts` に置く。テーマが大きくなったら、将来的に `src/theme/` ディレクトリへ分割する。

コンポーネントごとに場当たりで色を指定するのではなく、共通テーマと小さなデザイントークンを優先する。

## 発表時の説明文

```txt
子どもの頃はポケモンのタイプ相性を覚えていたのですが、フェアリータイプが追加されてから少し曖昧になっていたので、タイプ相性を学び直せるアプリを作りました。

このアプリでは、技のタイプと攻撃されるポケモンのタイプを選ぶと、相性倍率が即時に表示されます。2タイプ持ちのポケモンについても、それぞれの倍率を掛け算して、4倍や1/4倍、効果がない組み合わせを確認できます。
```

- データ取得: PokeAPIを当日叩かず、事前に用意したデータを使う
- タイプデータ: `types` / `type_effectiveness` はTypeScriptの静的データ
- ポケモンデータ: ポケモンタイプ当てクイズを実装する場合のみ、イベント前にSQLite + Drizzleで用意
- ポケモン範囲: イベント版は第1世代151匹の通常個体
- 将来拡張: `generation` 追加と `pokemon_forms` 追加で拡張可能にする
- 主機能: Mustはトップページとタイプ相性チェッカー
- Should: タイプ相性クイズ、チェッカーのsearch params共有、補正通知
- Won't for event: シルエットクイズ、詳細ページ、ダークモード
- 相性計算: CSRで実行する
- タイプ相性: 技タイプ → 防御側タイプで倍率を決める
- 2タイプ持ち: 各タイプへの倍率を掛け算する
- UI: タイプバッジ式、チェッカー防御側は2スロット式
- デザイン: 「キュートなきゅーたい」風のライトテーマ固定

## 今後の実装で最初にやること

1. `vp add @mantine/notifications`

6. タイプ相性チェッカーを作る
7. タイプ相性クイズへ展開する
