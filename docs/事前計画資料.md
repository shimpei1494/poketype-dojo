# TanStack Start 2時間開発イベント用アプリ計画

## アプリ概要

### 仮アプリ名

PokéType Dojo

または

PokéType Trainer

### コンセプト

子どもの頃にポケモンを遊んでいた大人向けに、ポケモンのタイプ相性を学び直せるミニアプリ。

特に、フェアリータイプ追加後の相性が曖昧になっている人でも、クイズや相性チェッカーを通じて楽しく覚え直せるようにする。

### 開発イベントの前提

- 複数人がそれぞれ2時間でアプリを開発するイベント
- 2時間後に自分の作ったアプリを発表する
- 商用利用はしない
- AIを使って開発する前提
- TanStack Startの良さも活かしたい
- データ準備やローカルDBのseedは事前に行ってよい

---

## 採用する方向性

### 基本方針

PokeAPIを当日叩くのではなく、事前にデータを用意してローカルDBに格納する。

理由:

- 当日の外部API依存をなくせる
- レスポンス速度が安定する
- 2時間イベント中にAPIやネットワークで詰まりにくい
- ポケモンやタイプ相性データは頻繁に変わるものではない
- TanStack Startのloader / Server Functions / DBアクセスを活かせる
- クライアント側では相性計算とUI操作に集中できる

## 最重要機能: タイプ相性チェッカー

### 目的

ユーザーが技タイプと防御側ポケモンのタイプを選ぶと、相性倍率を即時表示する。

### UIイメージ

txt 技のタイプ [でんき ▼]  攻撃されるポケモンのタイプ [みず ▼] [ひこう ▼]  結果 でんき → みず / ひこう  4倍ダメージ！ 効果抜群 × 2  内訳: でんき → みず: 2倍 でんき → ひこう: 2倍  2倍 × 2倍 = 4倍 

### 重要な表現

画面上では、単に「攻撃タイプ」「防御タイプ」と書くよりも、以下のように明確にする。

txt 技のタイプ 攻撃されるポケモンのタイプ 

理由:

- ポケモンのタイプ相性は「技のタイプ → 攻撃されるポケモンのタイプ」で決まる
- 「ほのおはくさに強い」という表現だけだと、攻撃側と防御側が混乱しやすい

---

## タイプ相性の計算仕様

### 基本

タイプ相性は以下で決まる。

txt 技のタイプ → 防御側タイプ 

### 単タイプの場合

ts finalMultiplier = getMultiplier(attackType, defenseType1) 

### 2タイプの場合

防御側ポケモンが2タイプを持つ場合、それぞれの倍率を掛け算する。

ts finalMultiplier =   getMultiplier(attackType, defenseType1) *   getMultiplier(attackType, defenseType2) 

### 例

txt でんき技 → みず = 2倍 でんき技 → ひこう = 2倍  でんき技 → みず / ひこう = 2 × 2 = 4倍 

txt でんき技 → ひこう = 2倍 でんき技 → じめん = 0倍  でんき技 → ひこう / じめん = 2 × 0 = 0倍 

### 表示する倍率

| 倍率 | 表示 |
|---:|---|
| 0 | 効果なし |
| 0.25 | いまひとつ × 2 |
| 0.5 | いまひとつ |
| 1 | 等倍 |
| 2 | 効果抜群 |
| 4 | 効果抜群 × 2 |

## 相性計算をCSRで行う理由

相性計算はブラウザ側で実行する。

理由:

- 18タイプ × 18タイプの小さなデータしかない
- 計算は単純な掛け算だけ
- ユーザーがタイプを入れ替えたとき即時反映したい
- サーバーに毎回問い合わせる必要がない
- UI操作の気持ちよさを出せる

### データ取得と計算の分担

txt TanStack Start loader / server   - types一覧をDBから取得   - type_effectiveness一覧をDBから取得   - pokemon一覧をDBから取得  React client   - 技タイプを選択   - 防御タイプ1を選択   - 防御タイプ2を選択   - 相性倍率を計算   - 結果と内訳を即時表示

### type_effectiveness

技タイプと防御タイプの相性倍率。

18 × 18 = 324行。

ts export const typeEffectiveness = sqliteTable('type_effectiveness', {   attackType: text('attack_type').notNull(),   defenseType: text('defense_type').notNull(),   multiplier: real('multiplier').notNull(), // 0, 0.5, 1, 2 }) 

例:

txt attack_type | defense_type | multiplier fire        | grass        | 2 fire        | water        | 0.5 electric    | ground       | 0 

DBでは、doubleDamageTo / halfDamageTo のような構造よりも、このように1行1関係で持つ方が扱いやすい。

### pokemon

短時間実装を優先し、pokemon_typesテーブルで正規化せず、type1 / type2をpokemonテーブルに持たせる。

ts export const pokemon = sqliteTable('pokemon', {   id: integer('id').primaryKey(),   name: text('name').notNull(),          // pikachu   jaName: text('ja_name').notNull(),     // ピカチュウ   type1: text('type1').notNull(),        // electric   type2: text('type2'),                  // null可能   spriteUrl: text('sprite_url').notNull(),   generation: integer('generation').notNull(), }) 

本格化する場合は、以下のように正規化してもよい。

txt pokemon pokemon_types 

ただし、2時間イベントではtype1 / type2方式の方が実装が速い。

## 2時間での優先順位

### 優先度1: /type-checker

最優先。

機能:

- 技タイプを1つ選択
- 攻撃されるポケモンのタイプを1〜2つ選択

- タイプ変更時に即時反映

### 優先度2: /quiz/type-matchup

タイプ相性クイズ。

機能:

- ランダムな技タイプを出す

- 次の問題に進める
